# Operating notes — proposed owner routine, not evidence of live monitoring

Assign a named operator and deputy before production. These are suggested checks, not a staffed SLA or a claim that alerts/scheduled jobs are configured. Capture UTC time, environment, release SHA, counts, decision and restricted evidence link without candidate text, credentials or private object keys. Use the read-only [operational diagnostics](REL_01_OPERATIONAL_DIAGNOSTICS.md) in a trusted connection; do not paste or automate their SQL in a browser.

| Cadence | Review and action |
| --- | --- |
| Daily after an authorized launch | Check availability and protected admin/client login, errors/rate-limit/security events, failed downloads and private-bucket access alerts. Inspect regeneration jobs by status/age, failed/max-three-attempt counts and stale pending work. The request-driven worker is bounded, not always-on. Investigate before retry or data changes. |
| Weekly | Check role/profile linkage anomalies, disabled-account access denials, current-document/file/Storage integrity counts, missing or wrong-bucket objects, duplicate current outputs, backup success and private object-byte inventory. Sample private read-back/checksums only under approved access. Review relevant audit events for unauthorized account, package, career, document and brand changes without exporting PII. |
| Each release and dependency review | Run `npm run release:verify`, review both production and full dependency audits/SBOM, triage residual findings, verify CI SHA and secret-scan result, and confirm Auth, Storage, CSP, rate limits, migration equivalence and rollback evidence. Do not promote merely because automated checks pass. |

For DOC-13, `pending`, `processing` and `failed` jobs are operational states, not downloadable documents. A max-attempt or aged job needs an owner to inspect non-sensitive failure codes, the current profile revision/package and document publication state before deciding on a controlled retry or repair. A nonzero missing-file/object, wrong-bucket or duplicate-current count blocks release and warrants incident triage. Legacy null-output rows require reviewed reconciliation, not guessed backfill. See [DOC-13 lifecycle](DOC_13_PERSISTENT_DOCUMENT_DELIVERY.md).

Escalate suspected cross-client access, compromised secrets, private-file exposure, lost document bytes, Auth outage or restore failure through the [incident response plan](assurance/INCIDENT_RESPONSE_PLAN.md). Preserve minimal evidence first; contain access and rotate compromised keys through the approved secret process, never in a ticket. For availability or integrity rollback, follow the [rollback procedure](assurance/ROLLBACK_PROCEDURE.md) and [DB-plus-Storage recovery plan](assurance/DISASTER_RECOVERY_PLAN.md). A provider backup is not proof of a completed restore drill. Final release approval and manual/provider closure remain separate [OPEN gates](REL_01_MANUAL_RELEASE_GATES.md).
