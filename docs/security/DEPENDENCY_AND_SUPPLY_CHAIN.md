The root advisories have **no patched upstream releases** as of this assessment. A root-level npm `overrides.argparse = 2.0.1` applies to Mammoth and the existing ESLint/js-yaml path (already 2.0.1). This replaces only the CLI parser dependency, not Mammoth itself. `npm ls` confirms no `sprintf-js` and DOCX extraction regression plus Mammoth CLI `--help` pass. The override is intentionally pinned and must be removed/re-evaluated when Mammoth upstream updates. No `npm audit fix --force`, downgrade or audit suppression was used.

Post-remediation policy: `npm audit --omit=dev` is a **blocking production gate** and currently reports zero; full `npm audit` still exits nonzero with five High dev-chain entries. CI keeps the production step blocking and the full audit step visible with a retained JSON artifact; a reviewer must triage that known residual and any new finding. No new runtime finding can be accepted merely because the full step is informational. `npm outdated` showed newer unrelated major versions of ESLint, PDF.js and TypeScript, but no supported patched version of either root advisory; unrelated major upgrades were not made.

Bundle evidence: the server-only extraction module imports Mammoth; search of `.next/static` found no Mammoth/argparse/sprintf/braces names. The server build contains Mammoth, but no `argparse`/`sprintf-js` name, consistent with the library/CLI split. `npm ls --omit=dev` excludes `braces` and the ESLint chain. Text search is supporting evidence, not proof that every possible runtime path is unreachable. Source files and private uploads still require adversarial parsing QA under the SEC-01 residual risk register.

Use `npm ci` from the lockfile, compare SBOMs, review install scripts and rerun both audits before each release. This is vulnerability classification, not certification or a substitute for an independent assessment.
