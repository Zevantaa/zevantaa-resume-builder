# Data protection overview

Candidate data includes contact details, work/education history, uploaded resumes/photos and derived PDFs. The service uses this information to prepare V1 resume and cover-letter outputs; no public self-registration is intended. Admins manage core identity/package fields; clients can access only their linked profile and permitted career/upload functions. Employer-facing privacy-masked copies are separate derived documents; originals remain unchanged. Masking is a product control, not a guarantee that free-text candidate content contains no identifying information—manual review remains important.

Uploads and outputs are intended to remain in private Storage. HTTPS and provider-managed encryption at rest are relied on; this project does not implement independent client-side encryption. Account disable blocks access but does not erase data. Retention/export/deletion require approved operational procedures; automatic erasure is not implemented. Database backups do not include Storage bytes, and a complete timed restore drill has not yet been evidenced. Data handling must be assessed against applicable contracts and law by business/legal owners; this engineering document does not assert legal compliance.
