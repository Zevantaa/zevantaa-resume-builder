## Findings and remediation

- **Low — unsafe clickable URL annotation in generated PDF.** Before this pass, the renderer accepted any `https:` link, including `https://127.0.0.1` and `.internal` hosts. This was **not** a server-side fetch or local-file read, but created an unsafe clickable link for the PDF reader. A failing PDF-level annotation test demonstrated the defect. The renderer now reuses the existing external-URL validator for HTTPS links and rejects control characters before creating mail/tel links. The malicious link text remains plain candidate-supplied text; it is not an active annotation. Related renderer and privacy tests pass.
- No other code vulnerability was confirmed in this local pass. Absence of a live attack result is not proof of remote RLS, bucket or deployed-session configuration.

## Boundaries and outstanding checks

The only project bucket for candidate source files and generated PDFs is `candidate-intake-private`; code never constructs public candidate URLs. The private bucket migration and absence of direct anon/auth object policies were reviewed locally. Remote state must be verified independently. The `branding/current/[kind]` route deliberately serves only approved logo/mark objects through fixed key patterns; it is not a candidate-file route.

Expected deployment-only checks (SEC/ASSUR live RLS, bucket policy and operational controls) remain separate release blockers. QAT-02 cannot be called fully closed until disposable admin and two-client sessions have exercised the manual rows above. No commit or push was made in this pass.
