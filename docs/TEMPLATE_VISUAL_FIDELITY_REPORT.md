## Visual QA decisions

1. Treat the five sparse trailing pages in the table as manual pagination review candidates, not automatic failures caused solely by an occupancy ratio. The first page can be full; moving all remaining content may be impossible without unsafe shrinking or loss. Each needs page-by-page content-flow review against the same verified fixture.
2. The Technology letter had one outside-page text run from an unbroken long URL. The renderer now inserts layout-only breaks for small HTTPS paragraphs; the focused regression test verifies page bounds and the regenerated edge PDF reports zero out-of-bounds runs.
3. Reference and application fonts differ (Arial/Helvetica/Georgia versus bundled Noto). Exact font substitution is not approved; a licensed, embedded-font decision is required before numeric fidelity thresholds are meaningful.
4. Future master comparisons must use the **same fictional structured profile** in reference HTML and app model. Compare A4/Letter dimensions, bounding boxes, key colors, font metrics, column ratios, page breaks, text content and extraction order. Flag clipped/overlapping text and missing facts independently of image differences. Existing script is a page-render/diagnostic foundation, not that final comparator.
5. No candidate facts were removed to force a page count. The supplied reference PDFs' fixed one/two-page counts are not ceilings for extensive histories.
