## Architecture and identifiers

- The renderer is `src/features/document-generation/pdf/render-pdf.ts`, fed by `PdfDocumentModel` from `pdf-model.ts` and `DocumentData` from `profile-mapper.ts`. It uses `@react-pdf/renderer`, bundled Noto font files, A4 and flowing sections. The supplied HTML uses Arial/Helvetica and, for some domestic references, Georgia; it is not a dynamic template and is not used at runtime.
- `document_records.version_number` and `file_records.version_number` version individual generated files. No template design version identifier or source hash is stored with each output. ATS algorithm versions are separate (`zevantaa-indicative-ats-v1`, `zevantaa-document-ats-v1`). This prevents exact historical design attribution.
- Current QA fixtures and PDF tests cover all 11 output IDs. `scripts/render-premium-document-examples.mjs` renders 44 fictional examples (short, normal, extensive, edge). `scripts/render-pdf-visual-qa.mjs` makes page PNGs and occupancy reports. The latter is not a master-to-output comparator.
- Existing client review lives in `client-resume-input-service.ts`, `client-resume-input-forms.tsx` and `confirm-client-resume-input-action.ts`. Document-linked scoring lives in `document-ats-assessment-service.ts` and `document-ats-comparison-service.ts`. The worker route is `src/app/api/internal/automation/route.ts`; the activation procedure is `docs/AUTOMATION_SCHEDULER_RUNBOOK.md`.
