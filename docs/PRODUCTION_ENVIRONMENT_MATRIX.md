For the chosen production origin `https://<approved-host>`, the exact allowlist entries are `https://<approved-host>/auth/callback?portal=admin` and `https://<approved-host>/auth/callback?portal=client`; the Site URL is `https://<approved-host>`. Replace the placeholder only in the provider dashboard after the domain is approved. The canonical URL must be a clean HTTPS origin, not a path, wildcard, preview URL, or localhost. Exact app-variable spellings above come from `src/lib/supabase/config.ts`, `src/lib/supabase/admin.ts`, `src/lib/security/rate-limit.ts`, recovery/provisioning code, and `scripts/validate-environment.mjs`.

In Vercel, configure production values in the Production environment only, with secret keys restricted to server runtime. Public `NEXT_PUBLIC_*` values are embedded into browser assets at build time: rebuilding is required after changing them. Run `npm run environment:validate -- production` against the target configuration before promotion. The clean CI build intentionally has no real Supabase credentials; dynamic protected pages defer those checks to requests. Validation checks syntax/presence, not ownership of the supplied Supabase project, Auth dashboard switches, email delivery, or live connectivity.
