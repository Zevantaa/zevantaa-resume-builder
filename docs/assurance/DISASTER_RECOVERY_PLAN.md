# Disaster recovery plan

Owner: release/incident owner; deputy and secure backup location must be designated before production. **No completed database-plus-Storage restore drill is evidenced.** Proposed planning targets, pending business approval: RPO 24 hours and RTO 24 hours. These are targets, not achieved guarantees; measure and revise in the first timed drill.

Verified architecture facts: application schema is represented by ordered `supabase/migrations`; candidate data and metadata reside in PostgreSQL/Supabase; private object bytes reside in Supabase Storage; Auth identities/configuration and deployment secrets are separate concerns. A database backup does **not** contain Storage objects. Supabase Free-tier projects may need scheduled off-site logical database dumps; confirm project plan and backup entitlement before relying on provider backups.

Prepare, with explicit authorization: (1) encrypted off-site PostgreSQL logical export or verified provider backup including schema/data/Auth dependencies; (2) independent private Storage object inventory and encrypted object backup with bucket, key, size and checksum manifest; (3) secure record of Auth redirects/provider settings, RLS/storage policies, deployment configuration **names** and a recoverable secret-vault procedure; (4) immutable Git SHA, lockfile, migration list and build artifact provenance. Protect backup access and define rotation/retention. Do not store actual secrets or CV files in Git.

Restore to isolated non-production infrastructure: identify backup timestamp, create separate Supabase project, restore DB and Auth-dependent state in the correct order, apply only missing reviewed migrations, restore private bucket objects, configure secrets/redirects from vault, validate grants/RLS, then deploy matching commit. Verify sample fictional or approved records, Auth roles, file hashes, private access denial, generation/download and audit writes. Measure data gap and elapsed restore time. Never overwrite production as the first drill. Capture failures and owner sign-off using [template](RESTORE_DRILL_TEMPLATE.md). Until a complete DB+Storage timed drill succeeds, SEC-01 production gate remains open.
