# Security disclosure process

Publish a dedicated security contact only after its mailbox, owner and response coverage are approved; no unverified address is advertised here. Until then, use the established private Sofiology/Zevantaa support channel for a confidential report. Ask reporters for affected URL/feature, safe reproduction steps, impact and contact method; explicitly request **no real candidate data, credentials or destructive proof**. Acknowledge during staffed business hours, assign severity under `VULNERABILITY_MANAGEMENT.md`, preserve evidence and coordinate remediation/notification with the incident owner. Avoid public issue threads for exploit details. No bug bounty, safe-harbor promise or 24/7 response is implied. Close with verified fix and agreed disclosure timing.
